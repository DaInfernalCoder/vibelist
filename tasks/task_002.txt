- Foreign key constraints link tables (e.g., `waitlist_id` references `Waitlists.id`)
- `NOT NULL` constraints on critical fields ensure data integrity
- Default timestamps using `now()` function
- Unique constraints on emails within a waitlist

**Database Trigger:**
```sql
CREATE OR REPLACE FUNCTION create_default_customization()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO customization_settings (waitlist_id, theme_color)
  VALUES (NEW.id, '#4F46E5');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER on_waitlist_created
AFTER INSERT ON waitlists
FOR EACH ROW
EXECUTE FUNCTION create_default_customization();
```

```sql
-- Function to get waitlist statistics
CREATE OR REPLACE FUNCTION get_waitlist_stats(waitlist_id UUID)
RETURNS JSON AS $$
DECLARE
  result JSON;
BEGIN
  SELECT json_build_object(
    'total_signups', COUNT(*),
    'confirmed', COUNT(*) FILTER (WHERE status = 'confirmed'),
    'pending', COUNT(*) FILTER (WHERE status = 'pending'),
    'conversion_rate', CASE 
      WHEN COUNT(*) > 0 THEN 
        ROUND((COUNT(*) FILTER (WHERE status = 'confirmed')::FLOAT / COUNT(*)) * 100, 2)
      ELSE 0
    END
  ) INTO result
  FROM waitlist_signups
  WHERE waitlist_id = $1;
  
  RETURN result;
END;
$$ LANGUAGE plpgsql;
```

## B. What are Database Migrations?

Database migrations are version-controlled scripts that manage database schema changes over time:

- **Implementation in this project:** Migration files in `scripts/migrations/` folder (e.g., `01_core_tables.sql`, `02_indexes.sql`)
- **Migration tracking:** A `schema_migrations` table tracks which migrations have been applied
- **Idempotency:** Migrations are designed to be safely re-runnable with checks like `CREATE TABLE IF NOT EXISTS`

## C. Error Resolution: `TypeError: supabase.sql is not a function`

The error occurred because the Supabase JavaScript client doesn't support direct DDL execution. The solution uses direct PostgreSQL connection:

```javascript
// Modified apply_migrations_direct.js
const { Client } = require('pg');
const fs = require('fs');
const path = require('path');

async function applyMigrations() {
  // Extract DB host from Supabase URL
  const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const dbHost = supabaseUrl.replace('https://', '').replace('.supabase.co', '.supabase.co:5432');
  
  // Create PostgreSQL connection string
  const connectionString = `postgresql://postgres:${process.env.SUPABASE_DB_PASSWORD}@${dbHost}/postgres`;
  const pgClient = new Client({ connectionString });
  
  try {
    await pgClient.connect();
    console.log('Connected to PostgreSQL database');
    
    // Read and apply migration files
    const migrationsDir = path.join(__dirname, './');
    const files = fs.readdirSync(migrationsDir).filter(f => f.endsWith('.sql')).sort();
    
    for (const file of files) {
      console.log(`Applying migration: ${file}`);
      const sql = fs.readFileSync(path.join(migrationsDir, file), 'utf8');
      await pgClient.query(sql);
      console.log(`Successfully applied: ${file}`);
    }
  } catch (error) {
    console.error('Migration error:', error);
  } finally {
    await pgClient.end();
  }
}

applyMigrations();
```

This approach ensures proper execution of DDL statements for creating and modifying the database schema.

# Diagnosis and Fix for 'TypeError: supabase.sql is not a function' in Migration Script:

## 1. Cause of the Error:

The error occurs because the `supabase-js` client doesn't provide a direct `sql()` method for executing raw SQL DDL statements. The client is primarily designed for data operations (CRUD) and RPC function calls, not schema migrations.

## 2. Correct Way to Execute SQL Migrations:

```javascript
// Before (incorrect approach)
const { createClient } = require('@supabase/supabase-js');
const supabase = createClient(process.env.NEXT_PUBLIC_SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY);

// In migration function
await supabase.sql(rawSqlString); // This fails with TypeError

// After (correct approach)
const { Client } = require('pg');
const connectionString = `postgresql://postgres:${process.env.SUPABASE_DB_PASSWORD}@${dbHost}:5432/postgres`;
const pgClient = new Client({ connectionString });

// In migration function
await pgClient.connect();
try {
  await pgClient.query(rawSqlString); // This works correctly
} finally {
  await pgClient.end();
}
```

## 3. Implementation Steps:

1. Add `pg` package: `npm install pg`
2. Update your `.env.local` to include `SUPABASE_DB_PASSWORD`
3. Extract the database host from your Supabase URL:
   ```javascript
   const dbHost = process.env.NEXT_PUBLIC_SUPABASE_URL.replace('https://', '').split('.')[0] + '.supabase.co';
   ```
4. Replace the Supabase client SQL execution with direct PostgreSQL queries
5. Ensure proper connection management with connect/end calls

## 4. Testing the Fix:

After implementing the fix, verify by running:
```bash

```

You should see successful migration execution without the TypeError.
